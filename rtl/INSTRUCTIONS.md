# SvaGenLean — Assertion Writing Reference

This file is a self-contained reference for writing `.lean` assertion files
against circuits generated by `sva_gen_lean --emit-lean`.  Read this instead
of re-reading the library sources every session.

---

## 1. What the tool generates

Running `sva_gen_lean --emit-lean foo.v` produces a `.lean` file that begins:

```lean
import SvaGenLean
open Verilog
```

For each Verilog module it emits three Lean definitions:

| Name | Kind | Description |
|---|---|---|
| `<Cap>_Input` | `structure` | One field per input port (clock excluded for sequential) |
| `<Cap>_State` | `structure` | One field per `reg` (sequential only; absent for combinational) |
| `<Cap>_Output` | `structure` | One field per output port |
| `<name>Circuit` | `def` | The `Circuit` value wiring everything together |

**Capitalisation rule**: module name `foo_bar` → struct prefix `Foo_bar` (only the
first character is upcased, the rest is left as-is).

### Combinational modules

```lean
def fooCircuit : Circuit Unit Foo_Input Foo_Output :=
  mkComb fun _inp => { out := _inp.a && _inp.b }
```

### Sequential modules (posedge clock, non-blocking assigns)

```lean
def fooCircuit : Circuit Foo_State Foo_Input Foo_Output :=
  mkSeq { q := false }                       -- initial state
    (fun _s _inp => { q := _inp.d })          -- step  (clocked update)
    (fun _s _inp => { q := _s.q })            -- observe (read registers)
```

The **clock port is not in `_Input`** — it is implicit in `step`.

## 2. Circuit model (`SvaGenLean.Model`)

```lean
structure Circuit (State Input Output : Type) where
  init    : State               -- power-on state
  step    : State → Input → State   -- one clock edge
  observe : State → Input → Output  -- combinational output function
```

`mkComb f` : combinational shorthand (`State = Unit`, step is identity).
`mkSeq s0 nxt obs` : sequential shorthand (explicit init/step/observe).

`runState c inputs t : State` — state after `t` clock edges given input
stream `inputs : Nat → Input`:

```
runState c inputs 0       = c.init
runState c inputs (n + 1) = c.step (runState c inputs n) (inputs n)
```

All three are `@[simp]`-friendly and unfold cleanly.

## 3. LTL operators (`SvaGenLean.LTL`)

`Formula α = (Nat → α) → Nat → Prop`  
The alphabet is **`Input × Output`** so atoms can reference both ports.

| Operator | Type | Meaning |
|---|---|---|
| `atom p` | `(α → Prop) → Formula α` | `p` holds at current time |
| `X φ` | `Formula α → Formula α` | `φ` holds at next time step |
| `G φ` | `Formula α → Formula α` | `φ` holds at all future times |
| `imp φ ψ` | `Formula α → Formula α → Formula α` | `φ → ψ` at current time |
| `iff φ ψ` | same | `φ ↔ ψ` at current time |
| `neg φ` | `Formula α → Formula α` | `¬φ` at current time |

`X` nests: `X (X φ)` = two steps ahead, `X (X (X φ))` = three, etc.

**`Circuit.satisfies`**:

```lean
c.satisfies φ  ≡  ∀ inputs : Nat → Input,
    φ (fun t => (inputs t, c.observe (runState c inputs t) (inputs t))) 0
```

The path type is `Nat → (Input × Output)`.  At time `t`, `io.1` is the
input and `io.2` is the output.

## 4. Writing assertions

```lean
import SvaGenLean
open Verilog LTL

-- paste or import the generated circuit definition here

-- atom helpers (optional but clean)
private def d_high  : Formula (Foo_Input  × Foo_Output) := atom fun io => io.1.d
private def q_high  : Formula (Foo_Input  × Foo_Output) := atom fun io => io.2.q

-- assertion
def my_prop : Formula (Foo_Input × Foo_Output) :=
  G (imp d_high (X q_high))

theorem my_theorem : fooCircuit.satisfies my_prop := by
  ...
```

## 5. Proof patterns

After `intro inputs k` (which unpacks `satisfies` → `G` → `∀ k`), the goal
is a statement about `runState` applied to concrete time indices.
`simp [LTL.iff, X, atom, runState, <circuitDef>, mkSeq]` (or `mkComb`)
unfolds everything in one shot for simple structural properties.

### Pattern A — single `simp` close (most common)

Works when both sides of the goal reduce to the same expression after
unrolling `runState`.

```lean
theorem sr_sin_q0 : shift_reg4Circuit.satisfies (G (iff (atom fun io => io.1.sin)
                                                        (X (atom fun io => io.2.q0)))) := by
  intro inputs k
  simp [LTL.iff, X, atom, runState, shift_reg4Circuit, mkSeq]
```

### Pattern B — intro hypothesis then exact

For `G (imp A B)` when B reduces to exactly A after unrolling.

```lean
theorem dff_correct : dffCircuit.satisfies dff_prop := by
  intro inputs k hd          -- hd : A holds at time 0+k
  simp only [X, atom, runState, dffCircuit, mkSeq]
  exact hd
```

### Pattern C — constructor for iff with non-trivial sides

When `simp` alone doesn't close an iff, split and handle each direction.

```lean
  intro inputs k
  constructor
  · intro h; simp [...] at *; exact h
  · intro h; simp [...] at *; exact h
```

## 6. Quirks and gotchas

**`Nat` not `ℕ`** — `SvaGenLean` does not import Mathlib.  The unicode
alias `ℕ` is not in scope.  Always write `Nat`.

**`runState` uses `Nat.zero` / `Nat.succ` patterns** — defined with
explicit `match`, not equation-style. `simp [runState]` unfolds it
correctly because `n + 1` reduces to `Nat.succ n` definitionally.

**Time index is `0 + k`** — `satisfies` starts at time `0`, and `G` adds
`+ k`.  The goal after `intro inputs k` has index `0 + k`, not `k`.
`simp` handles `0 + k = k` automatically via `Nat.zero_add`.

**`Bool` coerces to `Prop` as `= true`** — writing `atom fun io => io.1.d`
where `d : Bool` is fine; Lean inserts the `= true` coercion automatically.
The proof goal will show `... = true`.

**Clock is absent from `_Input`** — for sequential circuits, the clock port
is stripped from the input struct.  Never reference `_inp.clk`.

**Unassigned registers hold their value** — in the generated `step`, any
register not driven by a non-blocking assignment in the always block gets
`_s.<reg>` (identity).  This correctly models Verilog non-blocking semantics.

**`mkSeq` parameter names** — the three arguments are `s0`, `nxt`, `obs`
(not `init`/`step`/`observe`) to avoid shadowing the `Circuit` field names
inside the `where` block.

## 7. Quick example — DFF

```lean
import SvaGenLean
open Verilog LTL

structure DFF_State  where q : Bool
structure DFF_Input  where d : Bool
structure DFF_Output where q : Bool

def dffCircuit : Circuit DFF_State DFF_Input DFF_Output :=
  mkSeq { q := false }
        (fun _s i => { q := i.d })
        (fun s  _ => { q := s.q })

-- "If d is high at time t, q is high at time t+1"
theorem dff_correct :
    dffCircuit.satisfies (G (imp (atom fun io => io.1.d)
                                 (X  (atom fun io => io.2.q)))) := by
  intro inputs k hd
  simp only [X, atom, runState, dffCircuit, mkSeq]
  exact hd
```
